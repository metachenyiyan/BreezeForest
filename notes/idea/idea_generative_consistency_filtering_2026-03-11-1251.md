# Idea: Generative Consistency Filtering (GCF)

**创建时间**: 2026-03-11 12:51 UTC  
**推荐优先级**: ⭐⭐⭐ 最高优先级（推断阶段修复，无需重训练，替代 LZR）

---

## 问题定义

MultiBF 在生成阶段的问题可以精确定义为：

**不一致性（Inconsistency）**：组件 k 生成的样本 x_k = f_k^{-1}(z_k) 不"被认识"为属于组件 k。

具体表现为：
- 从组件 k 生成 x_k 后，计算模型对 x_k 的 responsibilities `r(x_k)`
- 如果 argmax_j r_j(x_k) ≠ k，即 x_k 被模型认为更像是来自其他组件 j 的样本，则 x_k 是一个"不一致生成"

**为什么不一致的样本往往落在 inter-cluster 区域**：
- 如果 x_k 落在 cluster j 的区域，则 r_j(x_k) 高，r_k(x_k) 低 → 不一致（argmax = j ≠ k）
- 如果 x_k 落在两个 cluster 之间，则所有 r_j(x_k) 都低 → r_k(x_k) 低 → 不一致（argmax 可能是任意 j）
- 如果 x_k 落在 cluster k 的核心区域，则 r_k(x_k) 高 → 一致（argmax = k）✓

因此，**过滤不一致的生成样本 = 过滤 inter-cluster 样本**。

**与 LZR（1235）的区别**：
- LZR：在 latent 空间通过"盒子"限制采样范围（预防性，推断前干预）
- GCF：在 data 空间通过"一致性检查"过滤生成结果（检测性，推断后干预）
- LZR 的缺陷：盒子边界基于轴对齐百分位数，忽略 latent 维度间相关性；如果 soft-EM 训练导致 zone 重叠，效果差
- GCF 的优势：不依赖 zone 估计，直接验证生成样本的"归属感"，理论上更精确

---

## 核心思路

**"生成者即所有者"原则**：一个好的生成样本 x，应当被其生成组件 k "认领"——即在模型的 responsibility 向量中，组件 k 的贡献应该最高，且超过一个置信度阈值。

**GCF 算法**：

1. 从 MultiBF 中超量采样（oversampling），生成 n_oversample 个候选样本
2. 对每个候选样本 x，计算 responsibilities `r(x) = softmax_{k}( log π_k + log p_k(x) )`
3. 对每个样本，判断：`r_{k_gen}(x) ≥ θ`，其中 k_gen 是生成该样本的组件，θ 是置信度阈值
4. 保留满足条件的样本，直到积累到目标数量 n_samples

**置信度阈值 θ 的含义**：
- θ = 1/K（均匀分布水平）：非常宽松，几乎不过滤任何样本
- θ = 0.5：常用阈值，要求生成样本的"所有者责任"超过 50%
- θ = 0.8：严格阈值，确保样本被非常清晰地归于一个组件

---

## 为什么它适合解决 multi-cluster 中间点生成问题

**直觉论证**：

考虑一个有 3 个 cluster 的 GAUSSIANS 数据集，使用 3 个组件的 MultiBF：
- 组件 0 主要覆盖 cluster A（左上）
- 组件 1 主要覆盖 cluster B（右上）
- 组件 2 主要覆盖 cluster C（下）

从组件 0 生成的 inter-cluster 样本 x*，其 responsibilities 会是：
- 如果 x* 在 cluster A 和 cluster B 之间：r_0(x*) ≈ r_1(x*) ≈ 0.4, r_2(x*) ≈ 0.2
- argmax = 0 or 1（不稳定），且 r_0(x*) = 0.4 < θ = 0.5 → **被 GCF 过滤** ✓

从组件 0 生成的 cluster A 核心样本 x_good，其 responsibilities 会是：
- r_0(x_good) ≈ 0.85, r_1(x_good) ≈ 0.10, r_2(x_good) ≈ 0.05
- argmax = 0, r_0(x_good) = 0.85 > θ = 0.5 → **保留** ✓

**数学上的严格性**：

设 p(x) = Σ_k π_k p_k(x)，责任 r_k(x) = π_k p_k(x) / p(x)。

如果样本 x 来自 cluster j（即 x 在 cluster j 的高密度区域）：
- p_j(x) >> p_k(x) for k ≠ j（cluster j 的组件密度远大于其他组件）
- 因此 r_j(x) >> r_k(x) for k ≠ j

如果 x 是 inter-cluster 样本（在低密度区域）：
- 所有 p_k(x) 都相对较小，但比例相近
- 因此 r_k(x) ≈ π_k（对所有 k），没有明显的"所有者"
- 最大 responsibility 约为 1/K（均匀水平），远低于置信度阈值

**与 OBRS（Verine et al., 2024）的关系**：
GCF 是最优预算拒绝采样（Optimal Budgeted Rejection Sampling）的一种特殊形式。OBRS 证明：对于给定采样预算，使用模型的密度比作为接受概率是最优的（在 f-散度意义下）。GCF 使用 responsibility 作为接受标准，是 OBRS 在混合模型上的具体实例。

## 与历史 idea 的关系

**明确替代 LZR（1235）**，同时也可以**与 LZR 叠加使用**（先用 LZR 限制 latent zone，再用 GCF 过滤）。

**为何 GCF 优于 LZR**：

| 维度 | LZR (1235) | GCF（本方案） |
|------|-----------|--------------|
| 工作阶段 | 生成前（限制 z 范围） | 生成后（过滤结果） |
| 依赖性 | 需要 calibrate_latent_zones() 预处理 | 无需预处理，直接使用模型输出 |
| Zone 准确度 | 基于轴对齐百分位数，忽略维度相关性 | 直接用模型密度函数，无估计误差 |
| 软训练模型效果 | zone 可能重叠（soft-EM 下 zones 不清晰） | 仍能过滤（高拒绝率但有效） |
| 组合能力 | 单独使用 | 可与 LZR 叠加（先限制后过滤） |
| 理论基础 | 参考 Stimper et al. (2022) | 参考 OBRS (Verine et al., 2024)，f-散度最优性 |
| 计算成本 | 推断时零额外成本（但需校准 forward pass） | 推断时 K 次 forward pass/样本 + oversampling |

LZR 在计算效率上有优势，GCF 在准确性上有优势。如果计算资源允许，**优先用 GCF；如果生成速度是关键，考虑先用 LZR 限制范围再用 GCF 细过滤**。

**与 ICDR（1240）** 的关系：ICDR 是训练时修复，GCF 是推断时修复，两者互补。

## 具体实现建议

### 步骤 1：添加 inverse_map_with_gcf() 到 MultiBF

```python
def inverse_map_with_gcf(
    self,
    n_samples,
    confidence_threshold=0.5,
    max_oversample_ratio=10,
    max_gap=1e-3,
    decay_ratio=1.0,
    verbose=False
):
    """
    Generate samples using Generative Consistency Filtering (GCF).
    
    A sample x generated by component k is kept only if:
        r_k(x) >= confidence_threshold
    where r_k(x) = softmax_k(log pi_j + log p_j(x))[k].
    
    Uses oversampling to account for rejection.
    
    :param n_samples: target number of samples to return
    :param confidence_threshold: minimum responsibility for the generating component
    :param max_oversample_ratio: maximum oversampling factor (1 = no oversampling)
    :param max_gap: bisection precision for inverse_map
    :param decay_ratio: bisection decay for inverse_map
    :param verbose: print acceptance statistics
    :return: (n_accepted, dim) tensor — may be fewer than n_samples if rejection rate is very high
    """
    weights = self.get_mixture_weights().detach()
    accepted_samples = []
    total_generated = 0

    for attempt in range(max_oversample_ratio):
        # Generate n_samples candidates this round
        component_indices = torch.multinomial(weights, n_samples, replacement=True)
        candidates = torch.zeros(n_samples, self.dim)
        candidate_generators = component_indices.clone()

        for k in range(self.n_components):
            mask = (component_indices == k)
            n_k = mask.sum().item()
            if n_k == 0:
                continue
            z = torch.rand(n_k, self.dim) * 0.98 + 0.01
            x_k = self.components[k].inverse_map(
                z, max_gap=max_gap, decay_ratio=decay_ratio
            )
            candidates[mask] = x_k

        total_generated += n_samples

        # Compute responsibilities for all candidates
        with torch.no_grad():
            log_pi = self.get_mixture_log_weights()  # (K,)
            comp_log_probs = []
            for k in range(self.n_components):
                ld_k = self._per_sample_log_det(self.components[k], candidates)
                comp_log_probs.append(log_pi[k] + ld_k)

            stacked = torch.stack(comp_log_probs, dim=0)  # (K, N)
            log_resp = stacked - torch.logsumexp(stacked, dim=0, keepdim=True)
            resp = torch.exp(log_resp)  # (K, N)

        # Consistency check: r_{k_gen}(x) >= threshold
        gen_resp = resp[candidate_generators, torch.arange(n_samples)]  # (N,)
        consistent = gen_resp >= confidence_threshold
        accepted_samples.append(candidates[consistent])

        n_accepted_so_far = sum(s.shape[0] for s in accepted_samples)
        if verbose:
            print(f"  Attempt {attempt+1}: {consistent.sum().item()}/{n_samples} accepted "
                  f"(total: {n_accepted_so_far}/{n_samples} target)")

        if n_accepted_so_far >= n_samples:
            break

    if len(accepted_samples) == 0:
        return torch.zeros(0, self.dim)

    all_accepted = torch.cat(accepted_samples, dim=0)

    if verbose:
        acceptance_rate = all_accepted.shape[0] / total_generated
        print(f"GCF: acceptance rate = {acceptance_rate:.3f} "
              f"({all_accepted.shape[0]}/{total_generated})")

    # Return exactly n_samples (or fewer if insufficient)
    if all_accepted.shape[0] > n_samples:
        idx = torch.randperm(all_accepted.shape[0])[:n_samples]
        return all_accepted[idx]
    return all_accepted
```

### 步骤 3：可选 - LZR + GCF 组合

先用 LZR 限制 z 的采样范围，再用 GCF 过滤，两者叠加效果最强：

```python
def inverse_map_lzr_then_gcf(
    self,
    n_samples,
    latent_zones,        # 来自 LZR 校准的 (lo, hi) 列表
    confidence_threshold=0.5,
    max_oversample_ratio=5,
    max_gap=1e-3,
    decay_ratio=1.0
):
    """LZR + GCF combined: restrict z range, then filter by consistency."""
    weights = self.get_mixture_weights().detach()
    accepted_samples = []

    for _ in range(max_oversample_ratio):
        component_indices = torch.multinomial(weights, n_samples, replacement=True)
        candidates = torch.zeros(n_samples, self.dim)
        candidate_generators = component_indices.clone()

        for k in range(self.n_components):
            mask = (component_indices == k)
            n_k = mask.sum().item()
            if n_k == 0:
                continue

            # LZR: restrict z to component k's latent zone
            lo_k, hi_k = latent_zones[k]
            z = torch.rand(n_k, self.dim) * (hi_k - lo_k) + lo_k

            x_k = self.components[k].inverse_map(z, max_gap=max_gap, decay_ratio=decay_ratio)
            candidates[mask] = x_k

        # GCF: filter inconsistent samples
        with torch.no_grad():
            log_pi = self.get_mixture_log_weights()
            comp_log_probs = []
            for k in range(self.n_components):
                ld_k = self._per_sample_log_det(self.components[k], candidates)
                comp_log_probs.append(log_pi[k] + ld_k)
            stacked = torch.stack(comp_log_probs, dim=0)
            log_resp = stacked - torch.logsumexp(stacked, dim=0, keepdim=True)
            resp = torch.exp(log_resp)

        gen_resp = resp[candidate_generators, torch.arange(n_samples)]
        consistent = gen_resp >= confidence_threshold
        accepted_samples.append(candidates[consistent])

        if sum(s.shape[0] for s in accepted_samples) >= n_samples:
            break

    all_accepted = torch.cat(accepted_samples, dim=0)
    return all_accepted[:n_samples] if all_accepted.shape[0] >= n_samples else all_accepted
```

### 超参数调优指南

| 参数 | 推荐范围 | 说明 |
|------|---------|------|
| `confidence_threshold` | 0.4 – 0.7 | 越高越严格，拒绝率越高。先用 0.5，可视化后调整 |
| `max_oversample_ratio` | 3 – 10 | 最大过采样比率。若模型专一化好，3 即可；若 soft-EM 训练，用 10 |
| 与 DA-EM 结合 | 推荐 | DA-EM 训练后的模型拒绝率低（<20%），高度推荐组合 |
| 与 LZR 结合 | 可选 | 先 LZR 限制 zone，再 GCF 过滤，组合效果最强 |

## 潜在风险 / 副作用

| 风险 | 描述 | 缓解方案 |
|------|------|---------|
| **高拒绝率** | 如果 soft-EM 训练导致组件高度混淆，大多数样本都不"一致"，生成非常慢 | 与 DA-EM 结合使用；降低 confidence_threshold；增加 max_oversample_ratio |
| **接受样本偏差** | 被保留的样本是"高置信度"样本，这可能使生成分布比真实分布更集中（cluster 中心附近密度过高）| 降低 confidence_threshold（0.4 以下）或只用 argmax check（不设 threshold）|
| **计算成本** | 每个候选样本需要 K 次 forward pass（计算 responsibility），成本是标准生成的 K 倍 | 批量处理（batch forward），K=3 时代价可接受；或先 LZR 减少 oversampling 需求 |
| **边界样本被错误过滤** | cluster 边缘的合法样本可能 r_k < θ（因为边缘处责任本就较低） | 降低 threshold；或改为只过滤 argmax ≠ k 的样本（最宽松的一致性检查） |
| **梯度问题** | GCF 是 non-differentiable 的（通过硬阈值选择样本），不能用于训练 | 仅用于推断，不涉及梯度；训练时仍用标准 train_forward |

---

## 推荐优先级

**⭐⭐⭐ 最高优先级（推断时修复，可立即应用于现有模型）**

理由：
1. **零训练成本**：无需修改训练代码，直接应用于已训练的 MultiBF 模型
2. **替代 LZR（1235）**：比 LZR 更直接（在 data 空间而非 latent 空间验证），不依赖 zone 估计精度
3. **与 DA-EM 完美配合**：DA-EM 训练后组件专一化更强 → r_k(x) 对属于 cluster k 的样本接近 1 → GCF 拒绝率接近 0，几乎不需要 oversampling
4. **理论依据充分**：OBRS（Verine et al., 2024）证明了 density-ratio 拒绝采样在固定预算下的最优性
5. **直接性**：直接验证"生成者即所有者"这一核心不变量，比任何 zone 估计方法都更精确

**与 DA-EM + AER 的协同效应**：
- DA-EM 训练后：组件专一，r_k(x) 对 cluster k 样本≈0.9+ → 拒绝率 < 10%
- 纯 soft-EM 训练时：r_k(x) 较低 → 拒绝率可能 30-60%，但仍能有效过滤 inter-cluster 样本
